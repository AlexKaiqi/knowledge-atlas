# 在知图中探索与维护

本 Skill 依赖完整仓库；下列路径相对本文件。先读 [维护指引](../../../AGENTS.md)、[当前路线](../../../task.md) 和 [产品目标](../../../PRODUCT.md)，检查已有改动与当前问题。使用你已有的模型、会话和工具，不在项目内创建新的 Agent 框架。

## 找到并继续问题

先找相关知识、探索及更具体的目录说明，确认是在 Git 自有内容还是网页服务记录上工作。沿用已有探索并明确继续哪一版本；没有现成资料时，按实际需要建立可读记录，不要求填固定表格。私人内容先留在 `.local/` 或仓库外，进入共享目录前遵循用户已授权的分享范围。

按问题选择追问、直接解释、查证、例子或实验。阅读 [方法调研](../../../docs/LEARNING_METHODS.md)，用有帮助的方法支持理解；不要机械提问、强制答题或把用户困住。

直接回应学习者时，使用 [对话指导](references/conversation.md)。本地网页的 Codex CLI 薄桥接会将这份指导与当前探索的有限上下文交给已有 CLI；它不代表整个仓库或所有私人记录都已提供给模型。

## 需要实践时

按 [环境资产维护](../../../docs/EXPLORATION_ASSETS.md) 找到 [已有环境](../../../environments/README.md)。已有环境合适就复用；不适合时允许参与者从需求建立草稿，按不同实验创建或派生环境。只调用现成运行命令和原生工具，不搭建调度平台。

网页环境共建与包往返也按上述资产说明操作：读取所选 source.id/version 和 files，先检查内容再落到全新私人目录，不在导入时执行配置。按实验补依赖、入口和说明，用已有工具实际构建与检验，保留源版本返回环境包，供有权限的参与者在原环境导入新版本。构建、运行和结论验证分别记录；并发版本先比较合并，不能自动覆盖服务或公开私人历史。

实际执行后，将有价值的输入、代码/环境版本、命令、结果与限制保存在 [探索目录](../../../explorations/README.md) 或明确的外部资产位置。运行实例可以结束，资料要能继续使用。运行失败或没执行要如实记录，不能把计划写成验证结果；不要清理未知归属的数据卷或用户工作目录。

## 沉淀与交接

依照 [知识审阅规范](../../../docs/KNOWLEDGE_REVIEW.md) 整理可复用发现：解释问题，提供依据，说明条件和未知，留下进一步检验方向。对适用方法记录判断及理由，区分自查、独立审阅和真人试学。

Git 自有知识在 [knowledge/](../../../knowledge/README.md) 维护，引用具体探索、运行和相关知识版本。关系说明方向和理由；不要以“相关”代替证据。服务导出是工作副本，修改副本不等于更新数据库，见 [Agent 使用说明](../../../docs/AGENT_USAGE.md)。

交接留下已知结论、未解决问题、修改的资产、真实验证结果与最有价值的下一步。项目路线变化更新 `task.md`；单次探索进度留在自己的记录中，避免根路线堆满聊天日志。
