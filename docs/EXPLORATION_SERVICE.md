# 探索资产、知识与可选协作服务

决策日期：2026-09-08。本次范围修正：项目组织知识与探索资产，通过 Skills 等方式接入已有开源 Agent；用户可 clone 后直接在自己的 Agent 中工作。此前自建 Agent Provider、模型循环、云调度和实时语音服务的路线撤回，不列为待实现能力。

## 1. 两个正式入口

仓库入口：问题 → 用户已有 Agent → 资料与探索目录 → 按需复用环境 → 保存代码、输入与结果 → 提炼知识 → 下一次接着工作。项目提供约定和资产，Agent 本身负责模型、会话和工具。

网页入口：阅读资料、保存探索、多人讨论、操作与分享成果、维护有权限的知识修订。本地网页通过已有 Codex CLI 回答当前探索，外部完整 Agent 也可以围绕明确导出的材料协助；托管服务未配置直接回复。AI 回复使用服务端 `agent:codex` 身份，外部工具没有可冒充用户的通用服务令牌。

两者服务于同一个目标，不要求所有人先部署网页。手机、语音和远程工作优先使用所选 Agent 已有客户端；本项目保留轻量阅读与协作，后续薄连接按真实需求选择。

## 2. 每份内容有明确归属

| 内容 | 权威来源 | 修改方式 |
| --- | --- | --- |
| Git 自有知识 | `knowledge/` 与 Git 历史 | 自由 Markdown，保留稳定引用、来源与修订理由 |
| 可共享探索及小型运行证据 | `explorations/` 与 Git 历史 | 留下问题、代码、输入/输出、实际版本和下一步 |
| 环境定义 | `environments/` 与 Git 历史 | Dockerfile、依赖锁、运行说明；配置按需增加 |
| 大型数据、镜像与有状态存储 | 明确的外部资产或本地存储 | Git 记来源、版本、取得方式和恢复说明，不存全部二进制 |
| 网页讨论、成员、成果、知识修订及私人偏好 | SQLite/D1 | 通过有权限的服务接口和基础版本修订 |
| 服务导出 | 原服务对象的工作副本 | 明确记录来源版本；修改副本不自动回写 |
| 既有教学种子 | `content/knowledge/`、`content/learning/`、`content/cases/` | 保持旧 ID 与页面兼容，按相关规则修订 |

新的 Git 目录目前是组织入口，不会自动更新网页索引。服务 SQL 与 Git 没有双向同步。要把一份服务导出整理成 Git 自有条目，先确认可分享内容，保留源对象/版本与派生关系；之后是明确的分支，不是两处同时拥有最终覆盖权。需要回写时由有权限的使用者比较并提交新修订。

私人资料放 `.local/` 或仓库外；不随代码和公共知识分享。`.local/` 与 `.data/` 被 Git 忽略，但不等于缓存或已备份，不能随意删除。

## 3. 目录与知识关系

先以一份可读正文开始，再按实际需要增加附件、代码或运行记录。Git 自有条目可用稳定目录名或显式 ID；迁移、合并、改名保留可追溯引用。知识可链接多个专题，不要求树状目录表达所有关系。

完整性按声明范围判断：解释什么、依据什么、有哪些条件或未知、如何继续检验。章节与表现形式自由，不要求每条知识是完整课程。方法适用性、事实审阅与真人试学独立记录，见 [知识审阅规范](KNOWLEDGE_REVIEW.md)。

现有服务支持 `prerequisite`、`explains`、`applies-to`、`example-of`、`contrasts-with`、`challenges` 六类关系。仓库中同样可以用带理由的链接表达方向和对应版本，无需为正文复制一套 JSON。先修关系依赖读者目标，不是强制门禁；来源引用另记，“相关”不能当成证据支持。

反向引用、专题、图谱和检索索引是可重建视图。新增或实质修订时检查已有类似条目和受影响的关系，不强行建立密集全图。服务关系读取与导出继续检查目标当前权限。

## 4. Agent 接入和维护

单一入口为 [.agents/skills/knowledge-atlas/SKILL.md](../.agents/skills/knowledge-atlas/SKILL.md)，参考接入见 [使用自己的 Agent](AGENT_USAGE.md)。Skill 帮助定位资料、运行现成环境、整理证据与检查知识；不实现模型 SDK、会话协议、调度器或自动巡检服务。

一个或多个现有 Agent 可以承担解释、执行与编辑，但实际作者、审阅者及验证方式必须如实记录。不能把同一编辑者的自查写成独立审稿或真人试学。

维护围绕具体问题：来源失效或变化、用户反例、相关知识修订、实验无法复现、重复条目。把原因、目标版本、拟议差异、影响范围和下一步留在相关记录中，依用户已有授权正常推进。未解决的冲突保留分歧，不定期无理由重写整个知识库。外部 Agent 的定时或长任务能力由使用者配置，知图不提供后台自主维护承诺。

## 5. 环境与运行是可接续资产

复用少量有明确用途的环境定义，每段探索有独立写入区。环境定义、镜像、容器实例、持久数据和单次结果分开管理；容器可重建，重要结果和数据可定位、可备份、可恢复。

Docker/OCI 适合需要系统依赖的探索，Dev Containers 提供兼容开发入口，Compose 仅在多个服务共同工作时加入。简单语言实验可直接用本地环境。选型与维护依据、运行证据、数据备份边界见 [探索资产维护](EXPLORATION_ASSETS.md)。不为这些约定建立新的执行平台。

现有网页本地 runner 是一次性 Python 适配：已有镜像、非 root、无网络、只读根、资源/输出/时间限制，输入和小型结果保存在 SQL。它没有可继续开发的持久工作目录，不自动变成仓库资产，也不能当作敌对多租户云沙箱。

## 6. 现有服务应保持的约束

`ws_*` 表保存探索、成员、消息、成果/版本、任务、知识/修订与私人偏好。身份由服务端解析，昵称和请求字段不授予角色；网关账号仅在受信适配器中使用，本地不信任伪造 Header。

探索共享开放讨论与成果，知识共享只开放明确选定的修订；不能把历史私稿和私人来源一并暴露。加入原子检查共享状态；探索改回私人后已有成员保留权限。目标知识收回共享时，读取和导出过滤无权限关系。

保存使用基础版本、不可变历史与事务。请求幂等绑定操作者、路径和内容摘要；重试不覆盖旧记录。执行领取使用条件更新与租约，取消后迟到结果不得入库；失败有真实状态。

本地恢复与云端访问触发的恢复是现有执行行为，不等于持续调度。`waiting_provider` 保留兼容，表示已保存的 Agent 待办；并无后台 Agent 推理。生成 HTML 继续隔离在 sandbox iframe，不持有主应用能力，不能因此宣称已经达到生产强隔离。

## 7. 易用性、数据与长期维护

现有浏览器语音需主动开启，转写后确认发送，支持逐条朗读；本站不保存原始音频，浏览器识别可能由厂商在线服务提供。停止录音、播放和任务分别处理。手机软键盘、弱网、后台切换和语音尚需实际验收。

服务只保存用户显式给出的目标、兴趣、帮助偏好，以及真实讨论和成果。把这些交给外部 Agent 时需遵循用户选择，不默认导出学习画像，不把停留时间或浏览完成当成掌握。

当前已有 SQL 迁移、事务、版本、权限、分页、执行取消和导出验证。后续优先验证全新 clone 的探索接续、代表性环境重建、数据恢复及成果引用；网页继续处理与其真实使用相关的账号、备份和体验问题。生产托管和长期运行若成为需要，选择现有能力，不把它们变成自研全套 Agent 的前置建设。

## 8. 依据与验证界限

学习方法与教育站点研究见 [LEARNING_METHODS.md](LEARNING_METHODS.md)。Agent Skills、Pi、OpenCode 的官方资料见 [AGENT_USAGE.md](AGENT_USAGE.md)；Docker、Dev Containers、存储与替代方案的一手资料见 [EXPLORATION_ASSETS.md](EXPLORATION_ASSETS.md)。这些是工具能力和组织设计的依据，不能据此宣称本产品的学习效果已经验证。

进展与当前待办仅在 [task.md](../task.md) 维护，避免把历史路线继续当作开发指令。


## 原生 Agent 与共同浏览器接入

本地对话接入 Codex app-server 原生消息流；实践接入 AIO Sandbox 的浏览器、终端、文件 MCP。工作面板用 browser-ui 显示同一 Chrome，允许参与者亲自操作；模型工具循环由 Codex 负责。权限、版本、配置与环境文件维护统一见 [浏览器接入](BROWSER_WORKSPACE.md)。它是现有本地服务的薄连接，托管 Worker 未配置云环境；工作文件没有自动变成公共知识或 SQL 成果版本。
