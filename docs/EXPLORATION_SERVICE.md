# 持续探索服务：产品、知识与 Agent 的共同底座

决策日期：2026-09-08。依据用户最新目标修正产品：Agent 长期维护、格式自由、对话表达意图、按需生成工作面板、可执行环境、手机与语音优先。这些交互借鉴是产品设计推论；学习方法的效果证据另见 [LEARNING_METHODS.md](LEARNING_METHODS.md)。

## 1. 使用者的体验

用户说“相关一定是因果吗？让我试试看”，建立一段探索。主持 Agent 理解目标和背景，选择举例、追问、查证或创建实验。用户可以操作实验，也可以直接说“把这个条件改一下”。其他人或专门 Agent 可在同一上下文中补充反例、材料和修改。主持 Agent 汇总分歧、已有结论与可继续的方向，避免多个机器人刷屏。

用户不需要知道 Docker、数据 schema 或工具清单。主交互保持“说出意图”，手工新建笔记或运行工具是可用入口，未来由 Agent 按需操作这些同一能力。缺少现成工具时生成一个独立成果；成熟工具经检查后进入可复用工具库。

桌面：最近探索 / 对话 / 工作面板。手机：单列讨论与成果切换，固定输入区；来源、历史和参与者按需展开。新成果可以提醒但不抢走焦点。软键盘、单手操作、弱网和后台恢复须经过真机验证，不能用响应式 CSS 代替验证。

## 2. 产品对象与真相来源

| 对象 | 作用 | 权威存储与关键约束 |
| --- | --- | --- |
| Actor | 人或服务身份；显示称呼不是身份 | 服务端解析凭据；客户端不能自称其他作者 |
| Exploration | 持续的问题空间 | SQL；稳定 ID、归属、可见范围、版本、时间 |
| Membership | 围绕一段探索的参与关系 | SQL；加入共享空间需原子检查当前权限 |
| Message | 讨论内容 | SQL 追加写；按游标分页；作者、客户端幂等标识 |
| Artifact / Version | 笔记、HTML、图表、工具、运行结果 | SQL 保存当前小型正文与不可变版本；大型文件以后放对象存储 |
| Job | 一次真实任务 | SQL 状态、冻结输入、租约、尝试、错误与产物引用 |
| Knowledge / Revision | 可复用解释与知识 | SQL 自由 Markdown、修订、依据、范围、审阅和关系 |
| Learning preference | 显式目标、兴趣、帮助偏好 | SQL 私人记录；可查看、改写、清空 |

数据库是服务状态的权威。目录是可恢复导出和 Agent 工作副本，Git 保存应用、方法规则与种子知识。不能让数据库和 Git 同时任意覆盖同一份正文。当前九个静态知识条目通过只读种子适配层继续使用，新探索沉淀的知识保存在服务中；统一迁移时保留旧 ID 和地址别名。

## 3. 完整知识不等于完整课程

完整性按声明范围判断：回答什么，解释是什么，依据是什么，条件与未知是什么，如何继续深入。一个解释可以很短；一个争议综述可能不提供唯一结论。章节、题型、图文形式由内容决定。

机器必须稳定处理身份、版本、引用、权限、大小与生命周期。来源和关系不能每次读取时临时依赖模型猜测，应由编辑 Agent 在写入时整理为可查询记录。`draft / maintained / archived` 表示生命周期，`private / shared` 表示可见范围；审阅与真人试学各有独立证据。`maintained` 意为纳入维护的正文，不宣称自动巡检已运行或主张已经证实。

推荐导出目录：

```text
knowledge/<stable-id>/
  index.md                  当前自由正文
  metadata.json             身份、当前版本、来源归属与关系
  revisions/<version>.md    允许导出的历史正文
  revisions/<version>.json  理由、作者、依据、审阅、关系
  assets/                   有需要才存在
collections/<topic>.md      专题视图，可引用多个知识
methods/                    学习方法、证据和审阅规则
```

不强制每个目录都包含所有文件。知识移动、改名不改变 ID；同一知识可属于多个专题。合并应保留别名，撤回保留历史，不打断已有引用。会话、私人学习记录和容器文件不混进公共知识树。

## 4. 关系维护到什么程度

先维护六类确实有用的关系：`prerequisite`（为某个学习目标补背景）、`explains`（解释）、`applies-to`（应用）、`example-of`（实例）、`contrasts-with`（对照）、`challenges`（挑战）。每条关系记录方向、目标、理由和对应修订。先修依赖读者目标，不是永恒门禁。来源引用单独记录，不把相似关系当成证据支持。

SQL 关系表足够。反向链接、专题、图谱和向量索引都是可重建视图。不得推断“甲有关乙、乙有关丙，所以甲支持丙”。维护 Agent 在新增、合并或实质修订时检查重复概念与受影响的关系，按需建议连接，无需建立密集的全知识图。

当前服务会校验目标是否存在并可见；目标收回分享后，其他读者不再获得关系详情。目录导出保留可访问版本的关系。图形化编辑、反向关系浏览和自动去重尚待增加。

## 5. 从讨论沉淀为知识

1. 保留原讨论与实验，允许没想清楚和不同意见。
2. 选中可复用成果的一个具体版本，创建知识私稿。实验结果先整理成解释或观察，不能直接把 stdout 当作公认知识。
3. 补充或核对依据、范围、反例、关系及方法适用性。知识格式自由。
4. 保存新修订，记录变更理由和基础版本。并发修改提示冲突；比较后合并再保存。
5. 明确选择共享该版本。分享知识仅开放明确共享的修订，之前的私稿历史不随之公开。

共享整段探索与共享选中的知识是两件事。前者开放整段讨论、成果和实验；后者只开放知识中选定的内容。已有读者可能保存共享副本，收回权限无法撤回他们已经看到的内容。

## 6. Agent 能做什么、怎样维护

建议拆成三个职责，可由同一模型实现：探索主持负责用户目标和节奏；执行 Agent 在隔离环境产出作品与验证记录；知识维护 Agent 负责提炼、来源、关系、版本与方法适用性。作者和审阅者的记录应可区分，即使暂时来自同一个模型，也不能假装独立审稿。

Agent 经受限服务接口创建消息、成果、实验与知识修订，不直接持有生产数据库或部署密钥。外部资料是材料，不是能够改写权限的系统指令。模型接入层以后负责模型调用、流事件、工具路由和预算；这些能力共享现有服务对象，不另造一份聊天数据。

维护以事件和风险驱动：来源变化/失效、用户反例、关联知识实质修改、实验失败、重复条目、复查到期。任务要输出具体差异或待办，不能周期性重写整个库。普通改善可根据维护策略自动合并；结论冲突需补依据或请求有能力的维护者处理，不要求所有编辑都有人批准。

维护任务应有：目标版本、触发原因、负责 Agent、预算/截止、适用检查结论、拟议差异、影响范围、失败原因及下一步。后续接入持久任务队列和到期复查调度。当前版本有通用执行任务和编辑自查，尚未启动自主巡检、自动关系推荐或自动合并知识。

## 7. 执行环境与恢复

```text
手机 / 桌面
    → 服务 API（身份、成员权限、探索与知识）
        → SQLite / D1（权威状态）
        → Agent provider（后续模型与语音）
        → 执行适配
            ├─ builtin：可信教学模型
            ├─ local Docker：受限 Python 环境
            └─ cloud containers：后续部署选择
        → 对象存储（大型作品、附件、音频，后续配置）
```

普通 Worker 不负责启动宿主 Docker daemon。Cloudflare Containers 可以作为一种执行适配，由 Worker/Durable Object 控制；独立 VM 与临时磁盘仍不等于持久数据库。容器结束前由服务接收并保存产物。

当前状态：`queued → running → succeeded / failed / cancelled`；模型未配置为 `waiting_provider`。任务领取通过条件更新与租约；提交结果必须持有当前有效租约。取消撤销租约，迟到结果不再入库。请求 ID 与内容摘要去重，真正重试生成新任务，引用上次输入，不覆盖失败记录。

本地有界队列扫描会恢复内置任务、启动最多两个容器；云端在读取工作区时执行有界恢复。租约超时后显示可重试失败。当前不保证无人访问时的云端调度，不能宣称已经具备长期云 Agent。接持续任务时需 durable queue/outbox、心跳与重试上限；队列可能重复投递，执行者必须幂等。

本地 Docker 使用已有 Python 镜像的实际摘要，不自动拉取镜像。非 root、无网络、只读根文件系统、无宿主挂载/密钥、限 CPU/内存/PID/输出、独立内部超时；结果写入数据库。它是开发环境验证的执行适配，不能直接作为敌对多租户生产沙箱。生产应接专用隔离执行主机或 VM/容器服务，检查权限、资源和网络策略。

生成 HTML 使用无同源权限的 sandbox iframe 和 CSP，不持有主应用能力。外部资源与 fetch 受限；原生 iframe 无法单靠 CSP 保证完全禁止自导航。生产强隔离预览还需要独立域、网络策略、验证消息协议与结果大小限制。主应用不能被 Agent 生成的 HTML 覆写。

## 8. 用户学习数据与语音

当前只保存用户主动提供的目标、兴趣、引导偏好，以及实际讨论、作品与执行历史。未来个人记忆可补“此任务卡在哪里、使用过什么提示、自己怎样解释、延后能否完成”，必须明确是观察还是推断，并允许查看、修正和删除。不要从停留时间推断掌握，不把偏好固化成学习风格分类。

本地访问者用 HttpOnly Cookie 区分身份，记录在 SQLite，清除凭据无法自动找回。Sites 平台在受保护网关提供稳定用户 ID 时，工作区使用该身份；该信任只在平台适配器内成立，不能开放绕过网关的 Worker 原始入口。本地服务不信任同名客户端 Header。旧版笔记仍保留原 cookie 归属；暂不自动合并账号，以免串档。

浏览器语音是第一层输入适配，可能使用浏览器厂商在线识别，用户主动开启后转写并确认；本站不保存原始音频。模型接入后可使用 WebRTC 实时语音与服务端短时凭据，处理连接、打断和已播放片段。停止说话或朗读不代表停止任务。原始语音的长期存储应另行选择，而非默认用于画像。

## 9. 长期不崩溃的工程次序

已具备：SQL 迁移、事务、不可变版本、幂等、权限边界、分页与输入上限、任务租约、实际取消及超时、导出和数据库重启验证。构建只清理生成页面，不清理 `.data`。

下一步按真实规模增加：

1. 接模型适配与受限工具调用，验证“说问题 → 生成工具 → 操作 → 修订知识”的完整真实 Agent 链路。
2. 生产持久队列、执行服务、对象存储与任务预算；长任务不得依赖浏览器存活。
3. 账号恢复/访客合并、成员管理、版务与滥用处理；先保留可回滚日志。
4. 自动备份与定期恢复演练、指标告警、维护队列和来源复查。
5. 真机语音、键盘、弱网和多人编辑验证；再做可校正的个性化。

没有承诺任意规模高可用。一个产物失效不能拖垮主应用，一个 Agent 失败不能阻断别人的学习，一次知识修订不能丢失历史；围绕这些故障边界逐步扩展。

## 10. 调研出处与采用的理由

- [Codex 云环境](https://learn.chatgpt.com/docs/environments/cloud-environment)：任务环境、执行验证和可复核产物；借鉴工作区与执行层分离。
- [长期任务](https://learn.chatgpt.com/docs/long-running-work)：持续上下文、补充要求和任务状态；本项目需要自己的持久调度才能达到类似行为。
- [可视化](https://learn.chatgpt.com/docs/visualizations)：按问题创建可操作图表、计算器与模拟；借鉴成果面板。
- [Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations)、[WebRTC](https://developers.openai.com/api/docs/guides/realtime-webrtc)：输入输出、打断和客户端会话；本轮浏览器识别不是 Realtime 接入。
- [W3C SKOS](https://www.w3.org/TR/skos-primer/)：稳定标识、多专题与关系语义；不引入完整 RDF 技术栈。
- [W3C PROV-O](https://www.w3.org/TR/prov-o/)：实体、活动与作者的轻量溯源思路。
- [MediaWiki Edit API](https://www.mediawiki.org/wiki/API:Edit)：基础修订检测编辑冲突；正文编辑不要求人人填写课程字段。
- [Worker 运行方式](https://developers.cloudflare.com/workers/reference/how-workers-works/)、[Containers 架构](https://developers.cloudflare.com/containers/concepts/architecture/)：控制服务与隔离执行适配。
- [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[Queues 投递语义](https://developers.cloudflare.com/queues/reference/delivery-guarantees/)：事务与至少一次投递下的去重责任。

上述站点说明的是设计与运行机制，不能用来证明本产品提升学习效果。教育有效性仍依赖具体教学设计与真实学习者证据。
