# 新知识与导学检查规范

规范依据见 [方法调研](LEARNING_METHODS.md)，结构化检查表见 `content/learning/methods.json`。这是一组研究启发下的产品标准，不是某篇论文验证的固定教学配方。

## 两种贡献门槛

自由贡献可以先是问题、资料、反例、观点或未完成解释，在讨论空间保留真实状态。正式知识条目必须说明准确主张、来源与适用边界；完整导学还必须包含目标、支架、活动和反馈。不要要求每个想法一开始就是课程。

## 新增与修改的过程

1. 阅读 `PRODUCT.md`，明确读者的问题、所需能力和知识认知状态。
2. 使用 `npm run scaffold:knowledge -- <id>` 创建知识草稿，填写准确陈述、来源、假设与非推论，设置版本。
3. 在 `content/learning/knowledge-guides.json` 补充 `question / intuition / example / check`。先做 wiki 条目可以不建立完整导学。
4. 如提供完整导学，在 `content/learning/questions.json` 添加问题对象，参考现有结构并填写对应的提示回答；不要把案例 runtime 字段强塞到通用导学。
5. 更新公开注册表与状态；`npm run publish:knowledge -- <id>` 在写入前检查配套解释和来源。复杂关联可在同一变更中准备，最终以完整 `npm run check` 为准。
6. 执行结构检查，并按下面标准人工审阅。编辑初稿使用 `editorial-draft`；只有有署名审阅记录时使用 `content-reviewed`；有可查的试学报告后才使用 `learner-tried`。
7. 保留修改理由与版本；从网页提交的提案可导出，维护者完成审阅后执行 `npm run apply:revision -- <提案.json>`，检查差异并发布新的内容版本。

## 程序会检查什么

`npm run validate:learning` 与 `npm run check` 均检查：

- 标识、版本、阅读时间、目标读者、情境、目标、知识和先修引用。
- 预测及迁移选择题的选项、合法答案索引和逐项解释性反馈。
- 直觉、机制、深入解释至少三层，每层具备例子和边界。
- 实践类型、操作变量或选择、观察目标、模型引用与限制。
- 提示问题和对应帮助一一齐备，反思与重访任务存在。
- 方法引用、下一问题、来源 URL 与知识注册表完整。
- 公开知识配套科普解释与来源齐备；模板占位文本不进入导学。
- 审阅状态真实可追溯；试学状态需要报告引用。

自动检查只校验结构和可解析引用，不保证网址存活、来源支持主张、题目正确、教学有效或不存在误导。

## 人工必须逐项判断

1. 问题自然吗？声明的读者能理解场景吗？先修能补齐吗？
2. 目标可观察吗？结束后能解释、比较、判断或完成什么？
3. 初始预测触及了什么误解？不会的读者能否获得直接帮助？
4. 解释是怎样从具体走向抽象的？每个新术语和类比的边界是否清楚？
5. 活动需要什么思考？操作与理解目标有没有实际关系？
6. 反馈是否解释错误原因并给出下一步，而不只有红绿对错？
7. 迁移题是否改变情境或假设？开放回答是否通过要点自查而非字数判定？
8. 关键主张有对应来源吗？引用是原始研究、官方说明还是作者推测？
9. 模型、事实、工程建议与个人观察是否区分？实验结果是否真实计算？
10. 修订是否保留争议、理由和版本？AI 是否夸大核验与理解状态？

## 试学记录模板

```text
单元 / 版本：
日期 / 评审者：
目标读者与已有背景：
独立任务（避免照抄已给答案）：
卡点与错误解释：
提供了哪些提示：
换情境任务表现：
延后回忆（如未做，写未做）：
本轮能支持什么 / 不能支持什么：
需要修改的内容：
```

自查完成、结构检查通过、内容审阅完成与真实试学是不同事实，不得互相替代。
