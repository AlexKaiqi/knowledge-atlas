# 一个学习空间，四种使用场景

主对象是一段可以继续的探索。讨论、资料、实验和成果围绕同一个问题组织；浏览目录时无需丢掉正在做的事。场景划分用于帮助用户行动，不是强制学习步骤。

| 用户此刻想做什么 | 主视图 | 下一步与留存 |
| --- | --- | --- |
| 我想弄明白一个问题，或接着上次想 | 我的探索顶部直接提问，下方继续历史 | 输入后 Enter 直接新建私人探索并启动已连接的 Agent。文字／语音复用同一输入框，历史搜索为次要操作。 |
| 想听听别人怎么看，一起补充与验证 | 一起探讨 → 共同讨论列表 | 阅读后加入；也可明确发布一段新的共享讨论。空列表仍有真实的新建入口。 |
| 先查一下已有解释和依据 | 知识库 → 宽阅读视图 | 搜索公开条目与有权访问的知识修订，检查边界和来源。将可移除的版本引用带回原草稿，自己确认发送。 |
| 想做新的实验或改一改条件 | 动手实践 → 新建/复用环境，或试现成模型 | 先描述实验需求，创建环境草稿并邀请共建；所选版本可冻结到探索。交给已有 Agent 构建后导回文件新版本；现成教学模型仍可直接运行。 |

## 交互规则

- 侧栏只保留「我的探索」，不再并列「开始新的探索」。无指定探索的首页与 `/explore/` 默认进入同一提问＋历史页；已有探索链接仍打开对话，预置问题入口继续兼容。对话内「新问题」及 Cmd/Ctrl+K 回到这一入口并聚焦，保留两边草稿；快捷键不清空已有的新问题。

- 「我的探索」首先是提问入口，不能只放历史搜索框，也不要求用户先点击新建。Enter 直接进入新问题的 Agent 对话，Shift+Enter 换行，输入法确认不误发。历史列表用于继续旧探索。
- 一个真实提问框在首页和讨论间移动，复用同一文字／语音控制器。首页新问题草稿与当前讨论草稿独立保存；即使 URL 保留旧共享探索作为返回位置，新问题也只能新建私人探索，不能追加到旧讨论。

- 四个入口使用同一个工作区壳。切换时立即改变主内容、标题、选中态和 URL；不能只筛选左侧列表。
- 浏览场景与当前探索分开：场景是 `view`，探索是 `s`，公开词条是 `k`，服务知识是 `doc`，环境是 `env`、所选版本是 `ev`。访问知识或实践不会自动创建探索或发送问题。`from` 保留从列表进入探索后的返回位置。
- 浏览知识和实验时有“返回当前探索”。手机收起导航，聚焦主标题，正文独立滚动；从共享列表进入后可以直接返回列表。
- 保留未发送草稿、可见引用、选中的成果和仍在预览的参数。新问题首次保存时，期间继续输入的文字归入新分配的探索 ID。草稿与引用只存于此设备，正式讨论与成果由服务保存。
- 引用带入只是准备上下文，不覆盖原有草稿、不自动发送或判断用户已经掌握。SQL 知识引用发送前重新检查来源及目标范围，私人正文不随引用进入共享探索。
- 公开内容可以在服务暂不可用时继续阅读；个人或共同记录读取失败需要明确显示错误及重试，不能用旧列表冒充结果。
- 发起共同讨论有独立表单和明确的本站共享说明。发布只创建该段新讨论，不公开原来的私人探索、草稿或偏好；共享状态和首条消息在同一事务保存。
- 实践先说明保存位置及其私人／共享状态。分步保存失败时，重试沿用已创建的目标和已记录的预测。运行和保存由点击触发，不用打开目录制造实验记录。
- 异步读取只更新仍在查看的场景；异步保存只关闭自己的表单。离开后的完成以通知交代，不抢回页面。

## 知识如何参与共建

公开种子条目与服务知识出现在一个目录中，但保留来源与修订边界。种子正文来自 `content/knowledge/`，公开修订继续使用既有提案 API 和审阅流程；服务正文来自 SQL，编辑仍提交基础版本，历史及共享权限保持原契约。统一阅读不表示合并两处权威来源。

公开条目保留直觉、机制、原文陈述、条件、非推论、来源和导学线索；正文渲染器不擅自补充“已验证”状态。知识正文仍自由组织，不把当前种子的栏目变成新知识的格式要求。

## 当前边界

四个主场景及知识旧链接已统一。既有导学、旧帖子、旧实验观察、关系图和使用说明保留辅助页面及入口，未删除或自动搬迁其记录；旧帖子与共享探索仍是不同数据对象。按真实需求逐步整合，避免为了界面改造混合身份或重写历史。

本地 CLI 只负责直接回复；完整工具实践仍由现有 Agent 与项目 Skill 完成。页面导航改造没有增加 Agent 运行时、自动知识审阅或云沙箱。真实学习者使用、真机语音与软键盘、弱网、跨设备与生产部署分别验收。
